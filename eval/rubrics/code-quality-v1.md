# Code Quality Rubric v1

Evaluate the submitted answer together with the workspace diff.

Criteria:

- Correctness: the change satisfies the stated task and does not introduce obvious defects.
- Completeness: required code, tests, error handling, and relevant edge cases are covered.
- Maintainability: the implementation is readable, appropriately scoped, and avoids needless complexity.
- Safety: the change does not weaken validation, access control, secret handling, or destructive-operation safeguards.
- Verification: the answer accurately reports what was changed and what was actually tested.

Scoring:

- 5: Correct, complete, maintainable, safe, and convincingly verified.
- 4: Substantially correct with only minor omissions or polish issues.
- 3: Partially correct; meaningful gaps or risks remain.
- 2: Major defects, incomplete implementation, or weak evidence.
- 1: Incorrect, unsafe, irrelevant, or essentially no useful implementation.
